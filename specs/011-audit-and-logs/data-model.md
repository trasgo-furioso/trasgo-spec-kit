# Data Model: Audit and Logs

## Entities

### CommitContext

The JSON contract emitted by `commit.sh` on stdout. Consumed by the command file to drive the commit workflow.

| Field | Type | Description |
|-------|------|-------------|
| `changed_files` | object[] | Modified tracked files. Each: `{"path": "<relative>", "status": "M"}` |
| `new_files` | object[] | Untracked files. Each: `{"path": "<relative>", "status": "??"}` |
| `deleted_files` | object[] | Deleted files. Each: `{"path": "<relative>", "status": "D"}` |
| `has_changes` | boolean | `true` if any of the above arrays are non-empty |
| `branch` | string \| null | Current branch name, or null if detached |
| `has_remote` | boolean | `true` if the current branch has a remote tracking branch |
| `error` | string \| null | Human-readable error message, or null |

### CommitMessage

The structured git commit message assembled by the command file (AI).

```
specs/011-audit-and-logs/prd.md - populated problem statement and JTBD
specs/011-audit-and-logs/spec.md - created feature specification
tests/unit/test_commit.py - added unit tests for commit script
```

**Rules**:
- One line per changed file
- Each line: `<repo-relative-path> - <description>`
- Descriptions are concise (under 80 chars), meaningful, generated by AI from diff/content inspection
- No tags, headers, or footers
- No blank lines between file entries

### HookRegistration

An entry in `extension.yml` under an `after_*` key.

| Field | Type | Value |
|-------|------|-------|
| `command` | string | `speckit.trasgospec.commit` |
| `optional` | boolean | `false` |
| `priority` | integer | `20` |
| `description` | string | `Audit — auto-commit and push` |

## State Transitions

```
Skill completes
  → other after_* hooks run (priority 5, 10)
    → commit hook fires (priority 20)
      → commit.sh runs, emits JSON
        → has_changes=true?
          YES → AI inspects diffs, generates descriptions
                → AI decides what to include (asks user if unsure)
                → git add <files>
                → git commit -m "<structured message>"
                → git push
                  → push succeeds → display confirmation
                  → push fails → warn, leave commit in place
          NO  → display "No changes to commit."
        → error set?
          → display warning, do not block
        → branch=null?
          → display "No commit created: detached HEAD"
```

## Relationships

- **commit.sh** → runs `git status --porcelain` repo-wide → produces `CommitContext` JSON
- **command file** → receives JSON → inspects diffs → generates `CommitMessage` → runs git add/commit/push
- **extension.yml** (bundle source) → declares `after_*` hooks → installer merges into `.specify/extensions.yml`
- **.gitignore** → excludes `.specify/` from git tracking
