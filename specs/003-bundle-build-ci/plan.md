# Implementation Plan: Bundle Build CI

**Branch**: `003-bundle-build-ci` | **Date**: 2026-08-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-bundle-build-ci/spec.md`

## Summary

Automate bundle validation, build, and catalog update via a local git pre-push hook. When a developer pushes commits containing `bundle/` changes to main, the hook runs `specify bundle validate` and `specify bundle build`, updates `catalog.json` with the correct version and raw.githubusercontent.com download URL, creates a separate build commit, and allows the push to proceed. Non-bundle pushes pass through silently. A setup script activates hooks via `git config core.hooksPath .githooks`.

## Technical Context

**Language/Version**: Bash 3.2+ (macOS compatible), Python 3.11+ (tests only)

**Primary Dependencies**: Git 2.9+ (core.hooksPath), Spec Kit CLI (`specify`)

**Storage**: Filesystem only — `catalog.json`, bundle zip artifact, `.githooks/pre-push`

**Testing**: pytest >= 8.0 via `.venv/bin/pytest`, testing bash scripts via `subprocess.run()`

**Target Platform**: macOS / Linux developer workstations

**Project Type**: Developer tooling (git hooks + setup script)

**Performance Goals**: Hook execution under 10 seconds for typical bundle builds

**Constraints**: No external dependencies beyond git and specify CLI; bash 3.2+ portability; no jq/yq required

**Scale/Scope**: Single-developer or small team; one bundle, one catalog
